Checklists & Tours · Page Specification

Checklist List

The guard's work queue — open checklists first, then each tour's remaining checkpoints inline under a small heading, with finished work collapsed into the background.

Purpose

The landing point for the Checklists top-level nav item (see Introduction — Navigation). Surfaces anything generated by a trigger the user needs to act on: clock in/out, scheduled time, checkpoint visit, incident type, or manually started.

Ordering principle: open work in front, completed work in the background. Open checklists render as tappable cards — In Progress before Not Started, since half-done work goes stale in a way unstarted work doesn't — each labelled with its next action ("Continue" / "Start"). Completed checklists collapse into a "Completed · N" section at the bottom, capped to the most recent 15; a glance-back to confirm "that one went through" is all this screen owes, with full history on Checklist detail and in Reports. The earlier design — a four-column status table defaulting to "All" — buried the row needing attention under the shift's completions, which only grow as the night goes on.

Start a checklist manuallyA manual-trigger (trigger_type = Manual) template must be visible to the user — Global, Role-restricted to a role they hold, or Personal and created by themPicker lists the eligible manual templates; choosing one and starting creates a new Checklist instance (assigned_to = self when the template's assignment mode is "triggering user," otherwise left for the role to claim) and opens it directly, per Active checklist. Hidden entirely when no manual template is visible to the user.
Tour sectionsSecurity roleRendered inline below the open checklists, one section per tour under a small heading (name, mode, remaining badge, progress bar) — per Tour progress, which specifies the per-mode rendering. Not a tab and not a separate page: a guard typically has exactly one active tour, and its steps belong on the page every round starts from. Tours with remaining checkpoints sort above completed ones, which dim with "Complete ✓"; a tour's visited checkpoints collapse into a "Visited this shift · N" disclosure inside its section, mirroring the completed-checklists disclosure. Without an active shift the steps still list, with a note that progress starts with a shift. Not shown to users without the Security role.

States & edge cases

  • Empty state — no checklists currently apply; distinct copy for "nothing assigned right now" vs. "you hold no roles with checklist assignments."
  • Personal templates — a checklist from a Personal-visibility template only ever appears for its creator, never for others holding the same role.
  • Role-restricted templates assigned to a role, not a user — any user holding that role sees the same unclaimed instance until someone opens (and implicitly claims) it.

Mobile vs. desktop

One vertical column on both: open checklists, then tour sections, then the collapsed Completed disclosure. The former mobile Checklists/Tours chip tabs and the desktop side-by-side split are gone — with tours inline there is nothing left to switch between.
