Checkpoints

Every checkpoint in the marina on one screen — for the jobs that are about checkpoints rather than about any one location.

Purpose

Reached from Admin Home, gated by manage_locations — the same permission as Locations and Tours, since a checkpoint is a fixture of a location and a member of tours.

This screen deliberately overlaps with Location Types & Locations setup, which can still create and edit a checkpoint inline while you're standing on its location. That remains the right affordance while building out the hierarchy. This page is the other half of the same data: creating checkpoints across many locations in one pass, auditing which ones nothing references, correcting GPS radii in bulk, and handing a batch to a tour — none of which are reachable from a tree that shows one location's checkpoints at a time.

Data shown

FieldSourceNotes
NameCheckpoint.nameEdited inline on the row.
LocationCheckpoint.locationNot shown on the row at all — checkpoints are grouped under their parent location, with the group heading carrying the full ancestor path. That is what lets a checkpoint simply be called "Gate": three doors at the Main Office read as Back Door / Conference Door / Front Door under one heading, instead of each name having to repeat where it is. Checkpoints with no location group last under "No location", since that's a defect to fix rather than a place to look.
UsageCheckpoint.tours + Checkpoint.checklist_templatesHow many tours include it and how many templates it triggers. Both empty earns an Unused badge — a checkpoint nothing references is almost always an oversight, and is otherwise invisible.
GPS & radiusCheckpoint.gps_coordinates / gps_validation_radiusUnder Details. Radius falls back to the marina-wide default from Marina Settings when empty.
Scan URLCheckpoint.guid_urlCopyable, as on Location setup — the two places the GUID URL is exposed. Still not shown on Checkpoint detail.

Actions

ActionGatingBehavior
Create checkpoints in bulkmanage_locationsPick any number of Locations from a searchable, parent-grouped multi-select; one checkpoint is created at each, named after its location. Locations that already have checkpoints are still offered, annotated with how many — a second checkpoint at one location is legitimate, and a repeat name gets a numeric suffix. One transaction regardless of count.
Rename a checkpointmanage_locationsInline on the row; no dialog.
Edit GPS / radiusmanage_locationsUnder Details. Clearing the radius restores the marina default rather than storing zero.
Add selected to a tourmanage_locationsSelect rows, pick a tour. Checkpoints already on that tour are skipped rather than duplicated. On a Linear tour they append to checkpoint_order, ready to be dragged into place on Tours setup.
Delete (single or selected)manage_locationsConfirmation states the real consequence: the scan URL stops working and any physical NFC tag or QR sticker encoding it becomes dead. Past CheckIn records are kept.
Select a whole location's checkpoints—Each group heading carries an All/None toggle with its count, so handing one dock's checkpoints to a tour is two clicks.
Filter—By name or location path, using the same short-term matching rule as the location picker ("c" matches the start of a word, so "dock c 14" doesn't match Dock A's Slip 14). A separate toggle narrows to checkpoints on no tour and no template.

States & edge cases

  • Checkpoint with no location — possible if its location was deleted. Collected into a "No location" group sorted last rather than hidden, since it can never be reached by a location-scoped tour and needs either relinking or deleting.
  • Unused checkpoint — surfaced, not blocked. A checkpoint created ahead of the tour that will use it is a normal mid-setup state; the badge exists so it doesn't stay that way silently.
  • Bulk-creating at a location that already has one — allowed. The new checkpoint's name gets a numeric suffix so the two are distinguishable without a rename.
  • Adding to a tour that already contains some of the selection — the overlap is skipped, so the action is safely repeatable and never produces duplicate membership.
  • Deleting a checkpoint that a template triggers on — the template survives with one fewer attached checkpoint. If it was the only one, the template stops triggering, which Checklist Templates already warns about on its own screen.

Mobile vs. desktop

Desktop is the primary surface — bulk selection and multi-column rows want the width. Mobile supports filtering, renaming, copying a scan URL, and editing one checkpoint's GPS, which covers the realistic on-site case of standing at a checkpoint and correcting it.
